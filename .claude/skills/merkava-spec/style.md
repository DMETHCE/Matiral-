# מדריך סגנון — תבנית מרכבה (אפיון פונקציונאלי)

מבוסס על ניתוח 1:1 של אפיון מרכבה אמיתי (`2v026-737.docx` — `/ILG/MM_MATIRAL_ASSIGN_CLASS`).

## 1. מבנה העמוד (גרסה רזה — לבקשת המשתמש)

- **אין כותרת עליונה** (הוסרו הלוגו, `מדינת ישראל`, `מרכבה`).
- **אין פוטר** (הוסרו מספרי עמוד, שם מסמך, פרטי מרכז כלל ירושלים). אין צורך ב-Header/Footer בכלל.
- שוליים ~1200–1300 DXA. גופן ברירת מחדל Arial.
- כלל RTL: כל פסקה `bidirectional:true`+יישור ימין; כל טבלה `visuallyRightToLeft:true`. מילה עברית בודדת מתהפכת ללא `bidirectional:true`.

## 2. פתיחת המסמך (עמוד 1 — רזה)

**אין טבלת מטא-דאטה ואין טבלת "מסמכים קשורים"** (הוסרו). עמוד 1 מכיל רק:
1. כותרת קצרה מודגשת: `מסמכים`.
2. בולט `✓` (מודגש): משפט תיאור קצר של מה הפונקציה עושה.

(אם המשתמש יבקש בעתיד להחזיר את ה-boilerplate הממשלתי — ראה היסטוריית הסקיל; השם הטכני של האובייקט ממילא מופיע בסעיף 4.2.)

## 3. גוף המסמך (מספור מתחיל ב-4)

- `4.   תיאור טכני מפורט` (כותרת גדולה מאוד, size ~36, מודגש שחור)
- `4.2  יצירת פונקציה חדשה לטובת תיק ההתקשרות` (size ~30)
  - טבלה: `שם הפונקציה החדשה` (תווית מוצללת) | `<שם הפונקציה>`
  - בולט `❖` (מודגש): `פונקציה מסוג RFC - לטובת <מטרה>`
- `4.2.1  מסך הקלט של הפונקציה :` (size ~26)
  - בולט `✓` `פרמטרים:` ← **טבלת פרמטרים** (ר' §4)
  - בולט `✓` `טבלאות:` ← `טבלת <NAME>` ← **טבלת מבנה** (ר' §4)
- `4.2.2  מסך הפלט של הפונקציה :`
  - בולט `✓` `פרמטרים:` ← טבלת פרמטרים
  - בולט `✓` `טבלאות:` ← טבלת מבנה לפלט; ואז שורה `טבלה - ( RETURN ( LIKE BAPIRET2`
- `5.   מהלך הפונקציה:` ← כאן כל הלוגיקה כצעדים + טבלאות מיפוי (ר' §5)
- `6.` … תתי-סעיפים `6.1 / 6.2 / 6.3` להשלמה, בדיקות והחזרה למשתמש
- `סוף.` (size ~40 מודגש)
- `היסטוריה של המסמך` + טבלה: `גירסה | תאריך | מבצע | תמצית העדכון` (RTL — `גירסה` מימין)

## 4. פורמט טבלאות הפרמטרים / המבנים (5 עמודות, RTL)

סדר מימין לשמאל. שורת כותרת מוצללת אפור.

**טבלת פרמטרים:** `פרמטר | סוג / אלמנט נתונים | אורך | חובה | תיאור`
**טבלת מבנה/טבלה:** `שדה | סוג שדה | אורך | חובה | תיאור`

- עמודת `חובה`: ערכים `כן` / `לא` (או ריק).
- עמודת `אורך`: מספרים בלבד (40, 18, 1; ל-DEC: `5,2`).
- העמודה הימנית (`פרמטר`/`שדה`) והעמודה השנייה (סוג) — בגופן Consolas (מזהים).

## 5. ★ טבלאות המיפוי (לב הלוגיקה — 3 עמודות)

לכל קריאה/שליפה/מילוי: משפט `…באופן הבא:` ואז טבלה.

מבנה (RTL): **עמודה ימנית** = שם השדה/הפרמטר ביעד · **אמצע** = `=` · **עמודה שמאלית** (כותרת `אופן האכלוס`) = הערך/מקור.

כותרות נפוצות לעמודה הימנית:
- שמירת קלט: `שם שדה / מבנה בסך הקלט` (שמאל: `שם המשתנה / מבנה זמני`)
- טבלה זמנית: `שם טבלה זמנית במסך הקלט` (שמאל: `שם טבלה זמנית`)
- קריאת BAPI: `שם הפרמטר ב <BAPI_NAME>` (שמאל: `אופן האכלוס`)
- שליפה/מבנה: `שם שדה ב <TABLE/CDS/STRUCT>` (שמאל: `אופן האכלוס`)

דוגמה מהמקור (מילה במילה):

| שם הפרמטר ב BAPI_OBJCL_CREATE | = | אופן האכלוס |
|---|---|---|
| OBJECTKEYNEW | = | LV_MATNR |
| OBJECTTABLENEW | = | 'MARA' |
| CLASSNUMNEW | = | LV_CHARACT_NAME |
| CLASSTYPENEW | = | '001' |

## 6. טרמינולוגיה קבועה (העתק מילה במילה)

- הוראה: `יש ל…` (לשמור / לקרוא לפונקציה / לייצר / להעביר / לבדוק / לסיים ולהחזיר)
- `באופן הבא:` — תמיד לפני טבלת מיפוי
- מעברים: `תחילה`, `לאחר מכן`, `בנוסף`, `בסיום`
- תנאים: `יש לבדוק האם …` , `במידה וכן …` , `במידה ולא …`
- סיום צעד: `… למשתמש`
- כותרת עמודת ערך: `אופן האכלוס`
- סוף החלק הטכני: `סוף.`

## 7. שמות וערכים

- קידומות (abap-ilg): `LV_` סקלר זמני · `LT_` טבלה זמנית · `IV_/EV_` סקלר קלט/פלט · `IT_/ET_` טבלת קלט/פלט · `P_` פרמטר בדיקה.
- ערכים קבועים בגרשיים בודדים: `'MARA'`, `'001'`, `'1'`, `'X'`, `'W'`, `WAIT='X'`.
- ערכי מערכת ללא גרשיים: `SY-DATUM`.
- שמות שדה ממבנה: `LT_CHAR-CHARCINTERNALID`, `LT_CHAR-VALUE`.
- טבלת החזרה תמיד `RETURN` מסוג `BAPIRET2`.
