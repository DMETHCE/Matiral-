# אפיון CDS — מעקב מסלול ירוק / בקרה מפצה

**התוצר:** שלושה CDS View Entities שמחזירים בזמן אמת את תמונת המצב המלאה
של כל סט במסלול הירוק — במקום תוכנית ה-Batch וטבלת היעד שתוכננו
(ניתוח התוכנית הישנה: `docs/abap/abap_program_analysis.md`).
**עקרון מנחה (הנחיית הלקוח, 26.08.2026):** האפיון העסקי (מסמך ה-Word)
גובר על התוכנית בכל סתירה.
**סטטוס:** ✅ מאושר; עבר ביקורת סוכני ABAP + CDS; מוכן לאקטיבציה ב-ADT.

---

## 1. האובייקטים ודרישות מערכת

| אובייקט | קובץ | תפקיד |
|---------|------|--------|
| `ZI_MM_GP_QMMASTATUS` | `src/cds/zi_mm_gp_qmmastatus.ddls.asddls` | דגלי קודים 50/60/70/80 לכל QMNUM מ-QMMA (`MNGRP='ZPU'`, ללא פעילויות שנמחקו) |
| `ZI_MM_GP_CLEARING` | `src/cds/zi_mm_gp_clearing.ddls.asddls` | תשלום בפועל מ-ACDOCA: שורות ספק שסולקו במסמך תשלום ('2%'), ledger מוביל |
| `ZC_MM_GREENTRACK` | `src/cds/zc_mm_greentrack.ddls.asddls` | ה-View הראשי: חיבור הכל + עץ ההחלטות |

**דרישת מערכת:** S/4HANA 2020 ומעלה (`define view entity`, ביטויים בתנאי
`ON`) — אושר על ידי הלקוח.

## 2. מקורות נתונים ותנאי קישור

כל הקישורים `LEFT OUTER JOIN` — "לא נמצא" נשאר ריק, כמצופה.

| מקור | Alias | קישור | הערה |
|------|-------|--------|------|
| `/ILG/MM_GRPO_DET` | `grpo` | בסיס; מפתח `MANDT+QMNUM` — שורה אחת לסט | מבנה אומת מול צילום SE11, 26.08.2026 |
| `ZI_MM_GP_QMMASTATUS` | `stat` | `qmnum = grpo.qmnum` | |
| `RBKP` | `inv` | `belnr = grpo.belnr, gjahr = grpo.gjahr` | מצב החשבונית הלוגיסטית: `RBSTAT` 5=נרשמה, 2=נמחקה |
| `BKPF` | `fi` | `awkey = concat(belnr, gjahr)` + `awtyp='RMRP'` + `bukrs = inv.bukrs` | הצמדת קוד החברה מונעת כפילות ברישום חוצה-חברות |
| `BKPF` | `rev` | מפתח מלא `bukrs = fi.bukrs, belnr = fi.stblg, gjahr = fi.stjah` כאשר `fi.stblg <> ''` | מסמך הסטורנו; סיבת הביטול `STGRD` נקראת ממנו |
| `T041CT` | `stx` | `stgrd = rev.stgrd`, `spras = $session.system_language` | טקסט סיבת הביטול (`TXT40`) |
| `ZI_MM_GP_CLEARING` | `clr` | `bukrs/belnr/gjahr = fi.*` | |

לאחר תיקוני הביקורת כל קישור הוא לכל היותר 1:1 — ה-View מחזיר **בדיוק
שורה אחת לכל QMNUM**.

| עמודה | מקור/נוסחה | הערה |

| `augbl`, `augdt` | `MAX` מ-ACDOCA (ledger מוביל, `KOART='K'`, `AUGBL LIKE '2%'`) | מסמך/תאריך תשלום |

## 4. עץ ההחלטות

מונחי עזר: **בוטלה** = מסמך סטורנו פיננסי (`STBLG` מלא) **או** חשבונית
שנמחקה (`RBSTAT='2'`); **הושלמו מסמכי המשך** = `MBLNR` ו-`BELNR` מלאים
**וגם** חשבונית רשומה (`RBSTAT='5'`); **שולם** = סילוק שורת ספק במסמך
תשלום (`AUGBL` מתחיל ב-'2', ledger מוביל).

סדר הבדיקות — הענף הראשון שמתקיים קובע:

| קוד | טקסט | תנאי |
|-----|------|------|
| 01 | נדחה לאחר אישור ובוטל | has_50 **וגם** has_60, וגם (בוטלה **או** לא שולם) |
| 02 | נדחה לאחר אישור ושולם | has_50 **וגם** has_60, שולם ולא בוטלה |
| 03 | נדחה לאחר אישור דורש | has_60 (בלי 50), וגם בוטלה |
| 04 | אושר והושלם לאחר עיסוק ידני | has_60, לא בוטלה, הושלמו מסמכי המשך, וגם (has_70 או has_80 או `MM_GR_DOC_IND` ∈ {2,4}) |
| 05 | אושר והושלם ללא תקלה | has_60, לא בוטלה, הושלמו מסמכי המשך, ללא סממני עיסוק ידני |
| 07 | אושר — טרם הושלמו מסמכי המשך | has_60, לא בוטלה, מסמכי המשך חסרים או חשבונית לא במצב "נרשמה" (חסר תקציב, תקופה סגורה, בהמתנה...) |
| 06 | נדחה על ידי דורש | has_50 בלבד |
| 99 | בתהליך | אף קוד |

הערות:

- **סטטוס 07 — תוספת מוצעת:** האפיון מזכיר "אושר ללא מסמכי המשך" אך לא
  מגדיר לו סטטוס; בלעדיו סטים כאלה היו מסווגים בשוגג "אושר והושלם".
  שם/התנהגות ניתנים לשינוי בהנחיית הגורם העסקי.
- ענפי 06/99 הם רשת ביטחון — סטים דחויים לרוב אינם נכנסים כלל לטבלת
  המסלול הירוק.
- סמנטיקת NULL של כל הענפים נבדקה על ידי סוכן הביקורת (סט בלי חשבונית,
  בלי רשומות QMMA, 50+60 בלי תשלום) — כולם נופלים לענף הנכון.

## 5. החלטות עסקיות פתוחות (לא חוסמות אקטיבציה)

1. **תשלום בתוך הסטטוס (סתירה פנימית באפיון):** דיון 4/8 קבע אינדיקטור
   בוליאני נפרד, אך צמד "ושולם/ובוטל" מגלם תשלום בסטטוס. מומש כלשון
   הדרישה העסקית (התשלום מכריע בענף 50+60) + אינדיקטור `is_paid` רוחבי.
2. **תשלום חלקי:** די בסילוק אחד במסמך תשלום כדי להיחשב "שולם". אם
   נדרש "שולם במלואו" — שינוי באגרגציית הסילוק.
3. **אישור סטטוס 07** (שם והתנהגות).
4. מהאפיון: חסימת ביטול סט מאושר; שיקוף 60+70+80 שקיבל אחר-כך 50 (כיום
   → ענף 50+60).

## 6. סיכוני תפעול מתועדים

- `LIKE '2%'` מניח שכל מסמכי התשלום מתחילים ב-2 בכל קודי החברה.
- `RLDNR='0L'` — אם ה-ledger המוביל שונה, לעדכן.
- ארכוב RBKP/BKPF/ACDOCA "ידרדר" סטטוסים ב-View חי — לתאם מדיניות שמירה.
- `logical_status` בעברית קבועה (כלשון האפיון); חלופה: טבלת טקסטים לפי
  `logical_status_code`.
- זוג `AUGBL`/`AUGDT` בסילוק מרובה עלול להגיע משורות שונות (MAX נפרד).

## 7. סטטוס אימות

**אומת מול צילומי SE11** (רישום מלא: `docs/tables/table_structures.md`):

- `/ILG/MM_GRPO_DET` — מבנה מלא (מפתח, שמות, טיפוסים) + `MNGRP='ZPU'`
  (צילום VIQMMA).
- `QMMA` — `MNGRP` (CHAR8), `MNCOD` (CHAR4), `KZLOESCH` — קיימים כמונח;
  מפתח `MANDT+QMNUM+MANUM` (כמה פעילויות להודעה — האגרגציה הכרחית).
- `RBKP` — מפתח `BELNR+GJAHR`, `BUKRS`, `RBSTAT` — קיימים כמונח.
- `BKPF` — מפתח, `AWKEY`, `AWTYP`, `STBLG`, `STJAH`, `STGRD`,
  **וגם `XREVERSED`** (אלמנט CO_STOKZ) — קיים ב-S/4, בניגוד לקביעת סוכן
  הביקורת; זיהוי הביטול חזר ל-`XREVERSED='X'` כלשון האפיון, והקישור
  למסמך הסטורנו נשאר דרך `STBLG`/`STJAH` (כי `AWREF_REV` מאוכלס על
  מסמך הסטורנו, לא על המקור).

- `T041CT` — 4/4 שדות: `SPRAS`+`STGRD` (מפתח), `TXT40` (אין TXT20).
- `ACDOCA` — מפתח `RLDNR`/`RBUKRS`/`GJAHR`/`BELNR` + `KOART`, `AUGBL`,
  `AUGDT` — כולם קיימים כמונח.

**🎯 אימות המבנה הושלם ב-100%: כל שדה שה-CDS משתמש בו, בכל שבע
הטבלאות, אומת מול צילומי SE11 מהמערכת (26.08.2026).**

**אימות נתונים שנותר (אופציונלי, לא חוסם):** שורת SE16 של תשלום בפועל —
לוודא ש-`AUGBL` מתחיל ב-'2' ושה-ledger המוביל הוא '0L'.
**אישורי לקוח:** S/4HANA 2020+; `AWTYP='RMRP'`; טבלת יעד לא תוקם;
המסמך גובר על התוכנית.

## 8. שלבי התקנה (ADT)

1. Eclipse ADT → חבילה ייעודית (למשל `ZMM_GREEN_PATH`) + Transport.
2. יצירת שלושה Data Definitions **לפי הסדר**: `ZI_MM_GP_QMMASTATUS`,
   `ZI_MM_GP_CLEARING`, ואז `ZC_MM_GREENTRACK` — הדבקת תוכן הקבצים
   מ-`src/cds/`.
3. אקטיבציה (Ctrl+F3) לפי אותו סדר.
4. Data Preview (F8) על `ZC_MM_GREENTRACK` מול סט מוכר.
5. בדיקות קבלה (סעיף 9) → שחרור Transport ל-QA.

## 9. בדיקות קבלה

לכל אחד מ-8 הסטטוסים (01–07, 99): לאתר QMNUM מייצג ולוודא סיווג נכון.
מקרי קצה: סט ללא חשבונית; חשבונית שנמחקה (`RBSTAT='2'`) לפני רישום
פיננסי; סטורנו MR8M (סיבת ביטול + טקסט מאוכלסים); סט 50+60 ששולם וסט
50+60 שלא שולם; סט 60 עם חשבונית בהמתנה (→ 07); סילוק בכמה מסמכי תשלום;
רישום חוצה-חברות (שורה אחת בלבד ל-QMNUM).
